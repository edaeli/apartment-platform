# Фактически выполненные проверки этапа 1

Дата: 11 сентября 2026. Среда: macOS 15.0, arm64.

## Подтверждено выполнением

- Проверены Apple Clang 15.0.0, CMake 4.3.4 и Git 2.39.3. Через Homebrew установлены Drogon 1.9.13 и SQLite 3.53.4 с зависимостями.
- Проект сконфигурирован и собран. В `compile_commands.json` подтверждён `-std=c++17` для кода проекта. `otool -L` подтвердил подключение библиотек Drogon и Homebrew SQLite.
- Дополнительно выполнена чистая конфигурация и сборка в новой папке `build-clean` с командой поиска зависимостей из README: успешно, без старого кэша CMake.
- `ctest --test-dir build --output-on-failure`: **2/2 теста прошли** (`database`, `http_smoke`). HTTP-тест выполнен с разрешением на локальный порт после отказа песочницы.
- C++ тест проверил ограничения схемы, внешние ключи на двух соединениях, параметры SQL, сохранение изменённых данных и закрытой истории при повторном заполнении, полный откат заполнения при искусственной ошибке.
- HTTP-тест запустил настоящий сервер с временной SQLite-базой: API, HTML, CSS, JavaScript и JPEG отдаются; аренда/продажа дают по 6 объявлений; неверный тип даёт 400, POST к listings даёт 405, файл базы не доступен по `/data/apartments.sqlite3`.
- Изменения цены и описания непосредственно в временной SQLite-базе появились в JSON. Закрытое объявление исчезло из доступных. Добавленный пользовательский объект сохранился после перезапуска.
- HTTP-тест остановил процесс, запустил его повторно и сравнил все строки трёх таблиц. Дубли и потери не обнаружены. Дополнительный `--init-db` также сохранил строки без изменений.
- `PRAGMA integrity_check` временной базы вернул `ok`, `PRAGMA foreign_key_check` — пустой результат.
- Рабочая база подготовлена двумя последовательными командами `./build/apartment_server --init-db`: оба раза 12 объектов и 12 объявлений. Прямой запрос SQLite подтвердил **12 / 12 / 36** строк в `properties` / `listings` / `property_photos`.
- Рабочий сервер запущен на `127.0.0.1:8080`. Отдельный `curl /api/health` подтвердил `status: ok`, `foreign_keys: true`, схему 1, SQLite 3.53.4 и 12/12 записей. Отдельный запрос аренды вернул 6 объектов с `deal_type = rent`.
- Синтаксис `public/app.js` проверен компиляцией через JavaScript `vm.Script`; ошибок синтаксиса нет. Это не проверка выполнения DOM в браузере.
- Создан отдельный локальный Git-репозиторий в папке проекта. `git check-ignore -v` подтвердил исключение рабочей базы, сборки, `.env`, `.env.local` и файла ключа. В списке исходников для Git нет рабочей базы и сборки. Коммиты и публикация на GitHub не выполнялись.

## Ограничения проверки

Визуальный просмотр в Safari и нажатия кнопок в настоящем браузере **не выполнены**: инструмент управления компьютером сообщил, что разрешения macOS Accessibility / Screen Recording не предоставлены. Автоматизированные проверки подтверждают сервер, данные, ресурсы и синтаксис JavaScript, но не заменяют проверку вёрстки, мобильного вида и DOM-поведения.

Ручная проверка: открыть `http://127.0.0.1:8080/`, убедиться в появлении 12 карточек и фотографий; выбрать «Аренда» и «Продажа» — в каждом разделе должно быть 6 карточек; вернуться на «Всё жильё». При уменьшении ширины окна каталог должен переходить с трёх колонок на две и одну.

Проверки регистрации, одновременного бронирования и перепродажи не выполнялись: эти функции намеренно не реализованы на первом этапе.
