# План этапов

## 1. Работающая основа — текущее задание

- Проверка среды, установка Drogon и SQLite.
- CMake, C++17, HTTP-сервер и небольшая обёртка над SQLite C API.
- Версия схемы 1: недвижимость, объявления, фотографии; ограничения целостности.
- 12 объектов, по 3 фотографии; повторяемый запуск без перезаписи данных.
- Каталог, разделение аренды/продажи, health и listings API.
- Проверка сборки, базы, API, перезапуска и интерфейса; документация на русском.

## 2. Полноценный каталог — следующий этап

- Увеличить демонстрационный набор до ~1000 объектов, сохранив идемпотентность генератора.
- Страница объявления, фотографии и местоположение.
- Фильтры района, цены, комнат; сортировка и пагинация на сервере.
- Сортировать в SQLite: `ORDER BY price ASC, id ASC` (и аналогично по площади/в обратную сторону). Это сортирует весь отфильтрованный набор **до** `LIMIT/OFFSET`, поэтому страницы согласованы. `id` разрешает равенство цен. Сортировка одной страницы в JavaScript дала бы неверный общий порядок.
- Выбирать столбец/направление по фиксированному белому списку в C++; значения фильтров передавать параметрами. Имена столбцов нельзя передавать как `?`.

## 3. Пользователи и сессии

- Отдельная миграция: `users`, серверные сессии; регистрация, вход, выход.
- Готовая библиотека безопасного хеширования (например, libsodium Argon2id); никакого собственного алгоритма.
- HttpOnly/SameSite cookies, срок жизни, CSRF-защита действий; Secure при HTTPS.

## 4. Бронирование и личный кабинет

- Миграция с `bookings`: пользователь, объявление, объект, состояние и даты. Внешние ключи, уникальное активное бронирование объекта; составная связь исключает несовпадение объекта и объявления.
- Транзакция `BEGIN IMMEDIATE`: проверить сессию, условно изменить `available` → `reserved`, проверить число изменённых строк, вставить бронирование, `COMMIT`. При ошибке — `ROLLBACK`.
- Тест с двумя независимыми соединениями и одновременно стартующими запросами: ровно один победитель и одно активное бронирование. На первом этапе такой гарантии бронирования ещё нет: самого действия нет.
- «Мои бронирования», освобождение аренды владельцем бронирования: то же объявление снова `available`.

## 5. Перепродажа

- В одной транзакции проверить пользователя, тип сделки, право перепродажи и положительную целую цену; закрыть старое объявление, завершить бронирование и создать новое для того же `property_id`.
- Повторное действие отклоняется по состоянию исходного бронирования. Уникальный частичный индекс в `listings` уже запрещает два незакрытых объявления для одного объекта.
- Тесты доступа другого пользователя, неположительной цены, повторных и одновременных запросов, сохранения истории.

## 6. Персонализация и подготовка сдачи

- Проверка требований, чистая сборка, документация и сценарий защиты.
