# План этапов

## 1. Работающая основа — завершён

- Проверка среды, установка Drogon и SQLite.
- CMake, C++17, HTTP-сервер и небольшая обёртка над SQLite C API.
- Версия схемы 1: недвижимость, объявления, фотографии; ограничения целостности.
- 12 объектов, по 3 фотографии; повторяемый запуск без перезаписи данных.
- Каталог, разделение аренды/продажи, health и listings API.
- Проверка сборки, базы, API, перезапуска и интерфейса; документация на русском.

## 2. Полноценный каталог — реализован

- Генератор расширен до 1000 демообъектов с постоянными ключами. Исходные 12 и пользовательские изменения сохраняются; число объявлений не ограничено 1000.
- Страница `/listings/{id}`, API `/api/listings/{id}`, полное описание и галерея. Местоположение указано адресом и районом; точная карта для демоданных не показывается.
- Совместные фильтры сделки, района, цены, комнат; четыре сортировки; пагинация 24 по умолчанию, максимум 100. Проверка параметров и понятные 400/404.
- Состояние каталога сохраняется в URL, есть сброс фильтров и состояния загрузки/ошибки/пустого результата.
- Миграция 2 с индексами, выполненный EXPLAIN QUERY PLAN, SQL-примеры и объяснения для защиты.
- Расширенные C++ и HTTP-тесты пройдены. Визуальная проверка Safari недоступна из-за разрешений macOS; ручной сценарий — в docs/verification.md.
- Сортировать в SQLite: `ORDER BY price ASC, id ASC` (и аналогично по площади/в обратную сторону). Это сортирует весь отфильтрованный набор **до** `LIMIT/OFFSET`, поэтому страницы согласованы. `id` разрешает равенство цен. Сортировка одной страницы в JavaScript дала бы неверный общий порядок.
- Выбирать столбец/направление по фиксированному белому списку в C++; значения фильтров передавать параметрами. Имена столбцов нельзя передавать как `?`.

## 3. Пользователи, сессии и бронирования — реализован

По заданию третий этап объединяет авторизацию и первоначальное бронирование.

- Миграция 3: `users`, `bookings`, история завершённых записей, внешние ключи и уникальные ограничения активной записи на объявление/объект. Старые таблицы и данные сохраняются.
- Регистрация, вход, выход, текущий пользователь; нормализованный уникальный email, Argon2id из libsodium.
- Сессии в памяти на 12 часов, случайные токены, ротация при входе, серверная инвалидизация при выходе; HttpOnly/SameSite cookies, Secure для HTTPS, CSRF, лимиты попыток входа.
- Бронирование: `BEGIN IMMEDIATE`, условный UPDATE, INSERT с зафиксированной ценой, COMMIT; при ошибке ROLLBACK. Ограниченное ожидание/повтор всей транзакции для конкурирующих писателей.
- Формы на русском, возврат к исходному объявлению, самостоятельное подтверждение без оплаты; «Мои бронирования» только для владельца.
- Пять CTest-тестов, включая одновременные HTTP-запросы от двух пользователей и проверку ровно одного победителя, отката, доступа и перезапуска. Сценарии Safari и точные ограничения проверки описаны в `verification.md`.

## 4. Освобождение аренды — запланирован

- В транзакции проверить пользователя, активность бронирования и тип аренды.
- Завершить запись (`released`, `ended_at`), сохранить её в истории; то же объявление снова становится `available`.
- Проверить чужой доступ, повторные/одновременные действия и возможность бронирования другим пользователем после освобождения.
- В текущем интерфейсе соответствующих кнопок нет.

## 5. Перепродажа

- В одной транзакции проверить пользователя, тип сделки, право перепродажи и положительную целую цену; закрыть старое объявление, завершить бронирование и создать новое для того же `property_id`.
- Повторное действие отклоняется по состоянию исходного бронирования. Уникальный частичный индекс в `listings` уже запрещает два незакрытых объявления для одного объекта.
- Тесты доступа другого пользователя, неположительной цены, повторных и одновременных запросов, сохранения истории.
