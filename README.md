# Свой адрес — учебный каталог недвижимости

Работающая основа сайта аренды и продажи квартир и домов: **C++17 + Drogon + SQLite + CMake**, интерфейс на HTML/CSS/обычном JavaScript. Все обращения к базе и серверная логика находятся в C++.

Завершены этапы 1–2: **1000 демонстрационных объектов в Ереване**, 500 первоначальных объявлений аренды и 500 продажи, квартиры и дома в 9 районах. Каталог поддерживает совместные фильтры, четыре сортировки, пагинацию и отдельные страницы объявлений с фотографиями. Цены в AMD; аренда — **в месяц**.

Четыре локальных JPEG из Unsplash повторяются в объявлениях: гостиная или внешний вид дома, кухня и спальня. У каждого демообъекта три записи фотографий, всего 3000. Это иллюстрации, **не реальные фотографии указанных адресов**. Источники и лицензия: [public/images/README.md](public/images/README.md). Адреса, характеристики и цены учебные; точная карта не показывается. Для работы после установки зависимостей интернет не нужен.

Регистрация, бронирование, перепродажа, избранное, история просмотров, рекомендации и ML пока не реализованы. Полные требования: [docs/requirements.md](docs/requirements.md), последовательность работы: [docs/plan.md](docs/plan.md).

## Установка зависимостей на этом Mac

Проверенная среда: macOS 15.0, Apple Silicon (arm64), Apple Clang 15.0.0, CMake 4.3.4, Git 2.39.3, Drogon 1.9.13, SQLite 3.53.4 из Homebrew. Python 3.11 используется только в интеграционном тесте; сервер его не вызывает.

Проверить инструменты:

```sh
sw_vers
uname -m
c++ --version
cmake --version
git --version
brew --version
drogon_ctl version
python3 --version
```

Apple Command Line Tools уже установлены. Если `c++` или `git` отсутствует на другом Mac, запустите установку и дождитесь её завершения:

```sh
xcode-select --install
```

Homebrew на текущем Mac находится в `/opt/homebrew`. При его отсутствии используйте официальный установщик на [brew.sh](https://brew.sh/). Установка зависимостей проекта:

```sh
brew install cmake drogon sqlite
```

`drogon` устанавливает веб-фреймворк и необходимые ему библиотеки; `sqlite` — библиотеку, заголовки для C++ и консольную утилиту. **DB Browser for SQLite этого не заменяет.** Если Python 3 отсутствует и нужны тесты:

```sh
brew install python
```

Homebrew SQLite не подменяет системный `/usr/bin/sqlite3`. Проект выбирает Homebrew-библиотеку через `CMAKE_PREFIX_PATH`; менять глобальный `PATH` не требуется. Версию можно посмотреть так:

```sh
"$(brew --prefix sqlite)/bin/sqlite3" --version
```

## Сборка

Все дальнейшие команды выполнять из корня проекта:

```sh
cd /Users/khoren/Documents/apartment-platform
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_PREFIX_PATH="$(brew --prefix);$(brew --prefix sqlite)" -DBUILD_TESTING=ON
cmake --build build -j 4
```

Для сборки только сервера без Python: при конфигурации укажите `-DBUILD_TESTING=OFF`. Сборка проекта использует `-std=c++17`, даже если установленная готовая библиотека Drogon была собрана другой версией стандарта.

## Подготовка базы и запуск

```sh
./build/apartment_server --init-db
./build/apartment_server
```

Откройте **http://127.0.0.1:8080/**. Пример прямой страницы: **http://127.0.0.1:8080/listings/1**. Обновление этой страницы работает. Сервер остаётся работать в терминале; остановка — **Ctrl+C**.

Перед запуском проверьте, свободен ли порт:

```sh
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

Если наш сервер уже работает, откройте его адрес. После пересборки остановите старый процесс через Ctrl+C в его терминале и только затем запускайте новый. Если порт занят другим приложением, выберите `--port 8081`.

`--init-db` создаёт схему, добавляет отсутствующие демообъекты и завершает программу. Обычный запуск делает ту же подготовку автоматически, затем запускает сайт. Обе команды можно повторять: существующие записи, цены, состояния и фотографии сохраняются. Версия схемы 1 автоматически обновляется до 2 миграцией `sql/002_catalog_indexes.sql`, которая добавляет индексы без пересоздания таблиц.

Генератор сохраняет исходные 12 объектов и создаёт отсутствующие ключи до `demo-1000`. Поля остальных объектов вычисляются из номера; повторный запуск воспроизводим. Существующий `demo_key` пропускается целиком. Генератор не ограничивает общее число объектов/объявлений: пользовательские объекты и будущая история перепродаж сохраняются сверх демонстрационной тысячи. `created_at` отражает фактическое время первого создания.

Рабочий файл базы на текущем Mac:

```text
/Users/khoren/Documents/apartment-platform/data/apartments.sqlite3
```

Другой порт (например, если 8080 занят):

```sh
./build/apartment_server --port 8081
```

Явные пути позволяют запускать из любой папки:

```sh
/Users/khoren/Documents/apartment-platform/build/apartment_server --root /Users/khoren/Documents/apartment-platform --db /Users/khoren/Documents/apartment-platform/data/apartments.sqlite3 --port 8080
```

`--root` указывает папку с `sql/` и `public/`; `--db` — файл SQLite (относительный путь считается от текущей папки терминала). По умолчанию база находится в `ROOT/data/apartments.sqlite3`. Сервер слушает только `127.0.0.1`. Статические файлы отдаются только из `public/`, база находится вне этой папки. Локальные рабочие каталоги Drogon также размещаются рядом с базой.

## API

```sh
curl --fail http://127.0.0.1:8080/api/health
curl --fail 'http://127.0.0.1:8080/api/listings?type=rent&min_price=200000&max_price=500000&rooms=2&sort=price_asc&page=1&page_size=24'
curl --fail --get http://127.0.0.1:8080/api/listings --data-urlencode 'district=Кентрон' --data-urlencode 'type=rent' --data-urlencode 'sort=area_desc'
curl --fail http://127.0.0.1:8080/api/listings/1
```

`GET /api/health` читает базу и возвращает состояние, версию SQLite/схемы, внешние ключи и количество объектов/объявлений. При недоступной базе — 503.

`GET /api/listings` принимает необязательные параметры; отсутствующий фильтр не ограничивает выборку:

| Параметр | Допустимые значения / по умолчанию |
| --- | --- |
| `type` | `rent` или `sale`; по умолчанию обе сделки |
| `district` | Точное название района, до 100 байт UTF-8, без управляющих символов; неизвестный район даёт пустую выдачу |
| `min_price`, `max_price` | Целые от 0 до 1 000 000 000 000 драмов включительно; минимум не больше максимума |
| `rooms` | Целое от 1 до 100, точное количество комнат |
| `sort` | `price_asc` (по умолчанию), `price_desc`, `area_asc`, `area_desc` |
| `page` | Целое от 1 до 1 000 000; по умолчанию 1 |
| `page_size` | Целое от 1 до 100; по умолчанию 24 |

Пример метаданных ответа без фильтров (поле `items` здесь не показано):

```json
{
  "count": 24,
  "total": 1000,
  "page": 1,
  "page_size": 24,
  "total_pages": 42,
  "has_previous": false,
  "has_next": true,
  "districts": ["Аван", "Аджапняк", "Арабкир", "Канакер-Зейтун", "Кентрон", "Малатия-Себастия", "Нор Норк", "Шенгавит", "Эребуни"]
}
```

`items` в настоящем ответе содержит 24 записи; `count` — их число на текущей странице, `total` — число подходящих объявлений **до** пагинации. `districts` — полный список районов из базы для формы, независимо от выбранных фильтров. При отсутствии результатов: `items: []`, `count: 0`, `total: 0`, `total_pages: 0`. Слишком далёкая допустимая страница даёт пустой `items`, сохраняя реальный `total`.

Все фильтры соединяются через `AND`. Выборка, сортировка и пагинация выполняются в SQLite. При равном значении цена/площадь используется `l.id ASC`. `COUNT` и выборка страницы читают один снимок базы в транзакции. Фотографии присоединяются **после** ограничения страницы, поэтому 3 фото не превращают одно объявление в 3 места выдачи.

Ошибочные, пустые, повторяющиеся или неизвестные параметры, неверные числа и сортировки дают **400** с JSON `{"error":"понятное объяснение"}`. Значения передаются через `sqlite3_bind_*`; фрагменты `ORDER BY` выбираются из четырёх фиксированных вариантов. Ошибки чтения базы — 500.

`GET /api/listings/{id}` возвращает одно объявление со всеми фотографиями, адресом, характеристиками, ценой, описанием и состоянием. Закрытое объявление доступно по прямому адресу, но отсутствует в каталоге. Несуществующий положительный `id` — **404**, нечисловой/неположительный/переполненный — **400**. `GET /listings/{id}` отдаёт HTML-страницу, которая получает эти данные из API; для отсутствующего объявления HTML тоже имеет статус 404 и показывает понятное сообщение.

Обоснование сортировки, индексов, `LIMIT/OFFSET` и полные SQL-примеры: [database-guide.md](docs/database-guide.md), [catalog-queries.sql](docs/catalog-queries.sql). Фактические планы: [query-plans.md](docs/query-plans.md). Универсально самого быстрого плана не предполагается.

## Использование каталога

Выберите сделку, район, цены и комнаты, затем нажмите **«Показать»**. Переключение сделки и сортировки применяется сразу. Применение изменённых условий возвращает страницу 1. **«Сбросить»** очищает условия и восстанавливает стандартную выдачу. Номер страницы меняется ссылками под карточками.

Параметры сохраняются в URL: адрес можно скопировать, обновить или открыть заново; кнопки браузера «Назад/Вперёд» восстанавливают выборку. Нажатие на фотографию или заголовок открывает объявление. **«Вернуться в каталог»** сохраняет условия и страницу, если объявление открыто из каталога. Миниатюры переключают большое фото.

Есть загрузка, сообщение об ошибке с повтором, пустой результат, 404 и заглушка для отсутствующего/недоступного фото. Текст из базы вставляется через `textContent`. Неработающих кнопок входа и бронирования нет.

## Проверки

```sh
ctest --test-dir build --output-on-failure
```

Тесты используют только память и временные отдельные базы; рабочую `data/apartments.sqlite3` не очищают.

- `database` (C++): внешние ключи, ограничения и запрет двух незакрытых объявлений, 1000/1000/3000 строк, параметры SQL, сохранение изменённых строк и закрытой истории, откат неудачного заполнения, обновление схемы 1 → 2 с сохранением пользовательских данных и произвольных id, отказ от неизвестной будущей версии.
- `http_smoke` (Python стандартной библиотеки): реальный C++ сервер на свободном локальном порту; совместные фильтры, четыре полных порядка с равными значениями, обход всех страниц без дублей, метаданные, граничные цены, пустая/далёкая страница, размер страницы до 100, неверные параметры/инъекции, прямое открытие/повторное получение страницы, 400/404, локальные изображения. Также проверяются чтение правок из SQLite, отсутствие фото, закрытая история, дополнительные объявления сверх 1000, перезапуск, повторный генератор и совпадение двух независимых демонаборов.

HTTP-тесту в песочнице помощника требуется разрешение на локальный порт. В обычном терминале специальный флаг не нужен. Подробности реально выполненных проверок и ограничения браузерной проверки — [verification.md](docs/verification.md).

## Просмотр в DB Browser

**Open Database / Открыть базу данных** → файл `data/apartments.sqlite3`. Вкладка **Database Structure / Структура БД** показывает таблицы и столбцы; **Browse Data / Просмотр данных** позволяет выбрать таблицу. Во вкладке **Execute SQL / Выполнить SQL** вставьте и запустите ▶:

```sql
SELECT id, address, district, area, rooms
FROM properties
ORDER BY id;
```

Это безопасное чтение всех объектов с адресом и характеристиками. Подробное объяснение таблиц, связей, `JOIN`, параметров и взаимодействия с C++: [docs/database-guide.md](docs/database-guide.md).

## Структура проекта

```text
CMakeLists.txt             сборка и регистрация тестов
src/main.cpp               параметры запуска, HTTP API и JSON
src/database.h/.cpp        соединение SQLite, запросы, миграция
src/seed.cpp               воспроизводимый набор 1000 демообъектов
sql/001_initial.sql        начальная схема, ограничения и индексы
sql/002_catalog_indexes.sql миграция с индексами каталога
public/                   HTML, CSS, JavaScript и локальные фотографии
tests/database_tests.cpp  проверки базы на C++
tests/http_smoke.py       проверка сервера и сохранения данных
docs/                    требования, план, объяснения и проверки
data/                    рабочая база (игнорируется Git)
build/                   результат CMake (игнорируется Git)
```

Короткие синхронные операции SQLite выполняются непосредственно в C++ обработчиках Drogon; соединения не разделяются между потоками. Для небольшого учебного каталога это понятная отправная точка. Перед ростом нагрузки можно добавить отдельные потоки работы с БД без изменения предметной модели.

`.gitignore` исключает базы и журналы, сборки, `.env`, ключи и локальные настройки IDE. SQL, генератор, тесты и фотографии входят в исходники. Перед будущей публикацией проверьте `git status --short`; база не должна попасть в отслеживаемые файлы. Публикация на GitHub в текущем этапе не выполняется.
